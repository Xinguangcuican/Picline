# Picline 0.1.9

基于 Tendedero 的本地修改版。按上游许可证要求使用独立名称和图标，保留原作者版权声明。

## 使用

运行 `build/Picline-0.1.9/Picline.app`。此版本默认使用简体中文，可从菜单栏的“语言”切换到 English 或跟随系统。

本次测试版为 0.1.9 / Build 10，独立副本位于 `build/Picline-0.1.9/Picline.app`，压缩包为 `build/Picline-0.1.9.zip`。之前的应用和压缩包保留。

### 0.1.9 更新

移除额外截图监视文件夹的数量上限。“添加文件夹…”不会因已经添加 3 个或更多目录而禁用，目录选择后的添加逻辑也不再限制数量。已有目录配置、重复目录检查、子目录监听和跨来源去重继续沿用。

本次通过 2 项现有目录监听回归测试、76 条文案检查、arm64 Release 构建、应用签名严格校验和 ZIP 完整性检查。

### 0.1.8 更新

已吸收 Tendedero 1.6.0 的五项交互改进，同时保留 Picline 的接收、去重和图片打开方式改造：

- 双击打开图片时不再先复制到剪贴板。单击复制会等待系统双击判定时间，右键菜单“复制”仍立即执行。
- 全屏应用中可以通过快捷键或菜单主动呼出，收起或切换 Space 后结束这次主动呼出状态。
- 没有卡片时，鼠标悬停菜单栏不会唤出空绳；快捷键和菜单仍可主动打开。
- 菜单栏图标在空绳时变淡，提示显示卡片数量，仍使用 Picline 自绘图标和剪贴板填实状态。
- 窄图片下的“已复制”提示保持一行。

App 图标采用已选定的米白底双照片、青色夹子方案。菜单栏使用单色的“绳线、夹子和照片框”图标，自动适配系统深浅色；开启剪贴板接收时照片框填实，关闭时显示轮廓。

### Snapzy

1. 在 Snapzy 中启用截图后的保存操作，确认导出位置，例如 `~/Desktop/Snapzy`。
2. 打开 Picline 菜单 → **接收其他文件夹的截图** → **添加文件夹…**，选择这个目录。
3. 新截图保存后会自动挂上绳子，按日期创建的子文件夹也受监视。添加目录时不会导入原有图片。
4. 可选：打开 **接收剪贴板图片**。同一截图经过多个文件夹或剪贴板时只挂一次。

### Shottr 或其他截图工具

将截图工具的输出目录加入 Picline，无需选择目录类型或去重模式。可以是保存目录，也可以是下面列出的 Shottr 临时目录。也可打开 **接收剪贴板图片**，接收工具复制的 PNG、TIFF、JPEG 或 WebP 图片。

**接收剪贴板图片** 与监听目录相互独立。开启后，从 Finder、微信、网页等位置复制的图片均可接收，不需要先添加其文件夹；纯文本和普通文件的图标不会被当成图片。支持一次复制多个图片文件。

剪贴板同时提供图片文件 URL 与 TIFF、PNG 等数据时，优先读取原图片文件，避免接收文件图标。图片临时文件已经失效或无法读取时，改用剪贴板附带的图片数据；图片附带文字说明不会导致整项被过滤。自身复制和标记为私密、临时或自动生成的剪贴板内容仍会忽略。

### 系统截图

不需要更改系统截图设置即可监视系统保存位置。可选的 **接收系统截图** 会将 macOS 自带截图工具的输出改到本应用的截图文件夹并关闭浮动缩略图，退出或关闭选项时恢复设置。此选项不会改变 Shottr 或 Snapzy 的配置；主要使用第三方工具时，可在首次询问中选择“暂不开启”。

## 双击图片打开方式

菜单栏 → **双击图片打开方式**，选择 **系统默认**、**预览**、**Shottr** 或 **Snapzy**；也可通过 **其他应用…** 选择本机的其他编辑器。

选择会自动保存，之后双击卡片或右键选择“打开”，都会将这张卡片对应的图片文件交给所选应用。默认使用系统的文件关联。未安装的应用显示为不可选；选定应用之后若被移除或打开失败，会提示临时使用系统默认应用或取消，保留原有选择。

录屏继续使用系统默认播放器。交给编辑器的是卡片对应的文件，编辑器采用覆盖保存还是另存由该编辑器决定；在原路径保存的修改会更新卡片。

## 文件与交互

- 文稿、桌面等普通目录继续引用原文件：取下不会删除原文件；明确选择“移到废纸篓”仍会删除文件，标记操作仍会编辑该文件。
- 系统临时目录，以及 `~/Library/Containers/<应用标识>/Data/tmp/` 中的图片会自动保存私有副本。Shottr 的临时文件消失、改名或被清理后，已接收的副本继续保留在绳子上；标记和丢弃只作用于副本。
- 剪贴板来源会在需要时保存私有副本；如果同一文件已经通过目录挂入，则继续使用已有引用。新安装的副本位于 `~/Library/Application Support/Picline/Screenshots/`，权限为仅当前用户可读写。已有安装继续沿用 `~/Library/Application Support/CaptureLine Preview/Screenshots/`，以保留卡片路径及系统截图设置。
- 可直接监视 Shottr 的 `~/Library/Containers/cc.ffitch.shottr/Data/tmp/cc.ffitch.shottr`。极短寿命的临时图片不再等待两次稳定扫描，但仍要求读取成功且图片完整可解码。其他无法按系统目录结构识别的应用缓存，仍建议改用持久导出目录。
- 文件未写完会在后台有限重试；后续文件变化也会再次触发接收。覆盖卡片对应文件会更新卡片及其内容指纹；另一份已合并文件被编辑后，会作为不同内容接收，避免覆盖原卡片。
- 所有图片来源默认按解码后的像素和方向去重，不增加设置项。同一目录、不同目录或剪贴板中的相同图片，只要已有卡片仍在绳上，就合并展示，不限时间；反复拖出不会新增卡片或再次弹出绳子。两次有意截取完全相同的内容也会合并。
- 去重仅覆盖仍在绳上的卡片，包括暂时隐藏或滚动到屏幕外的卡片；摘下后，相同图片可以再次接收。重启时从现有卡片重建指纹，也会合并旧版留下的重复卡片；合并不删除重复源文件。
- 当前运行中已关联的其他文件可以在原引用失效后用于恢复：只有像素仍相同才保存私有副本并保留原卡片的位置。没有可用关联文件的普通引用，仍沿用原文件删除后卡片移除的行为。
- 去重采用精确匹配，裁剪、标注、缩放或有损压缩改变了像素的图片会作为不同内容处理；录屏不参与图片去重。
- 没有截图区域元数据的图片直接挂入，有区域元数据的图片沿用飞入动画。
- 图片上限为 64 MiB、8000 万像素。录屏沿用原有收件箱支持，不受图片字节上限限制。

此版本支持将卡片交给其他应用打开；接收入口仍是目录与剪贴板，未加入外部主动投递、URL Scheme 或网络接收服务。

## 开发与验证

菜单栏 → **开源声明** 可直接查看上游来源、原作者及完整许可证，内容随应用打包，离线可读。“上游项目”按钮可打开原项目仓库。

```sh
scripts/build-picline.sh
swift test --disable-sandbox
swift scripts/check-strings.swift
python3 scripts/package-source.py
```

`build-picline.sh` 默认构建当前 Mac 架构的 Release 应用并输出 `build/Picline.app` 和 `build/Picline.zip`，使用 ad-hoc 签名；它不安装到 Applications，也不签署 Developer ID 或公证。Picline 沿用本地预览版的应用标识与偏好设置，监控目录、编辑器选择、语言及现有卡片无需重新配置。

可设置 `PICLINE_OUTPUT_DIR` 将应用和压缩包输出到独立目录，保留其他版本。

源码打包命令收集当前工作区的源代码、测试、本地化资源、构建脚本、图标及项目文档，包含尚未提交和新增的文件。包内附 `SOURCE_MANIFEST.json` 文件清单和 SHA-256 校验值，不包含 Git 历史、构建缓存、编译产物或未采用的上游品牌素材。解压后即可按上述命令构建，无需图片生成服务。

目录测试依赖 macOS FSEvents，需要能连接系统文件事件服务的普通进程环境；限制系统服务访问的执行沙盒中可能收不到通知。测试图片仅创建在仓库的 `build/intake-tests/` 下，剪贴板测试使用内存中的 `NSPasteboardItem`，不会读取或改写系统剪贴板。

1.6.0 试合并阶段已通过 50 项回归测试及 76 条界面文案检查，包括旧截图目录延续和新安装目录选择。接收与打开行为回归测试包含延迟重复投递、跨目录及剪贴板合并、重启恢复、旧重复卡片合并、文件编辑后的关联分离、匹配文件恢复和摘下后重新接收。剪贴板测试另覆盖图片附带文字、Finder 文件内容优先、微信文件 URL 与 TIFF 混合格式、临时文件失效回退、普通文件图标过滤和无效图片数据过滤；新增交互测试覆盖单击、双击、长按和丢弃按钮。构建后需退出旧应用并打开 Picline，再复制图片，验证实际交互。

本机的预览、Shottr、Snapzy 均已验证能通过应用标识定位；打开路由、选择持久化、应用不可用和录屏边界通过隔离测试验证。已实机捕捉到 Shottr 临时路径失效后卡片被移除的行为，并用短寿命源文件和真实卡片清理逻辑补充回归测试。
